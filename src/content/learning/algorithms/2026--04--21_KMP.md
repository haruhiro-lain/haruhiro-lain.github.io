# KMP 算法详解

KMP（Knuth-Morris-Pratt）是经典的**字符串匹配算法**，用于在主串 `text` 中查找模式串 `pattern` 的出现位置。

它最核心的价值是：

- 暴力匹配遇到不等时，主串指针会回退，存在重复比较。
- KMP 通过预处理模式串，做到**主串指针不回退**，整体时间复杂度降到 $O(n + m)$。

其中：

- $n$ 是主串长度。
- $m$ 是模式串长度。

---

## 1. 为什么暴力匹配会慢？

暴力匹配的思路很直接：

1. 主串从某个起点开始，尝试和模式串逐字符匹配。
2. 一旦失配，模式串回到开头，主串起点右移一位再试。

问题在于：

- 当模式串有大量重复前缀时，很多字符会被反复比较。
- 最坏情况下时间复杂度是 $O(nm)$。

KMP 的优化方向就是：**失配后，模式串应该跳到哪里，才能利用已经匹配过的信息？**

---

## 2. KMP 的核心概念：LPS（或 next 数组）

KMP 先对模式串做一次预处理，构建一个数组：

- 常见名称：`lps`、`next`、`prefix`。
- 本文统一用 `lps`。

`lps[i]` 的含义：

> 对于子串 `pattern[0..i]`，它的“最长相等真前后缀”的长度。

解释几个词：

- 前缀：从开头开始的子串。
- 后缀：到结尾结束的子串。
- 真前缀 / 真后缀：不能等于整个串本身。

例如 `"ababaca"`：

- `pattern[0..4] = "ababa"`
- 最长相等真前后缀是 `"aba"`
- 所以 `lps[4] = 3`

---

## 3. 如何构建 lps 数组

设：

- `i`：当前要计算 `lps[i]` 的位置（从 1 开始）。
- `len`：当前已知的最长相等前后缀长度。

构建规则：

1. 若 `pattern[i] === pattern[len]`：
	 - `len++`
	 - `lps[i] = len`
	 - `i++`
2. 若不相等：
	 - 如果 `len > 0`，令 `len = lps[len - 1]`，继续比较（`i` 不动）。
	 - 如果 `len == 0`，则 `lps[i] = 0`，`i++`。

关键直觉：

- 失配时不是从头再来，而是把 `len` 回退到“次长可用前后缀”，继续尝试。
- 这一步让预处理仍保持线性复杂度。

---

## 4. 匹配阶段怎么用 lps

匹配时用两个指针：

- `i` 指向主串 `text`
- `j` 指向模式串 `pattern`

过程：

1. 如果 `text[i] === pattern[j]`，两者都右移。
2. 若 `j == m`，表示完整匹配：
	 - 记录起点 `i - m`
	 - 继续找下一个匹配，令 `j = lps[j - 1]`
3. 若失配：
	 - 如果 `j > 0`，令 `j = lps[j - 1]`（主串 `i` 不回退）
	 - 如果 `j == 0`，只能 `i++`

这就是 KMP 快的原因：**主串下标 `i` 整体只会向前走。**

## 5. JavaScript 实现（返回所有匹配位置）

```js
function buildLPS(pattern) {
	const lps = new Array(pattern.length).fill(0);
	let len = 0;
	let i = 1;

	while (i < pattern.length) {
		if (pattern[i] === pattern[len]) {
			len += 1;
			lps[i] = len;
			i += 1;
		} else if (len > 0) {
			len = lps[len - 1];
		} else {
			lps[i] = 0;
			i += 1;
		}
	}

	return lps;
}

function kmpSearch(text, pattern) {
	if (pattern.length === 0) return [];

	const lps = buildLPS(pattern);
	const result = [];

	let i = 0; // text pointer
	let j = 0; // pattern pointer

	while (i < text.length) {
		if (text[i] === pattern[j]) {
			i += 1;
			j += 1;

			if (j === pattern.length) {
				result.push(i - j);
				j = lps[j - 1];
			}
		} else if (j > 0) {
			j = lps[j - 1];
		} else {
			i += 1;
		}
	}

	return result;
}

// demo
console.log(kmpSearch('ababcabcabababd', 'ababd')); // [10]
console.log(kmpSearch('aaaaa', 'aa')); // [0, 1, 2, 3]
```

## 6. 复杂度分析

- 构建 `lps`：$O(m)$
- 匹配过程：$O(n)$
- 总时间复杂度：$O(n + m)$
- 额外空间复杂度：$O(m)$

---

## 7. 常见易错点

1. **`lps` 定义不统一**
	 - 有些教材的 `next` 会整体右移或包含 `-1`，本质等价。
	 - 做题时只要和实现保持一致即可。

2. **失配时 `i` 不要乱回退**
	 - KMP 的核心就是主串不回退。

3. **匹配成功后要继续找后续匹配**
	 - 不要直接结束，尤其是题目要求返回所有位置时。

4. **空模式串边界处理**
	 - 需提前定义行为（本文返回空数组）。

---

## 8. 什么时候用 KMP？

适合场景：

- 单模式串匹配，且文本较长。
- 需要稳定线性复杂度，不希望被最坏情况卡住。
- 算法题中查找子串下标（如 `strStr` 类题目）。

如果是多模式匹配，可进一步了解 Trie + AC 自动机。

---

## 9. 一句话总结

KMP 的本质不是“匹配得更快”，而是“**失配时不浪费已经匹配的信息**”。

把 `lps` 真正理解透，KMP 就不再是模板题，而是非常自然的状态转移过程。
